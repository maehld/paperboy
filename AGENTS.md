# Project knowledge and working rules

## Goal and communication

Paperboy is a display service for ePaper displays (own firmware on ESPHome with deep sleep, ADR 0041; OpenDisplay is not supported by the service yet). Providers push JSON into a shared data document (ADR 0032) or run as exec provider programs from the instance's providers directory (ADR 0036, 0037); Paperboy renders pages from YAML templates and delivers them according to a plan per device. Evolved from SolarAI's display service `displayd` (ADR 0028, 0029).

- Communicate with the user in German.
- Everything in the software is English: identifiers, comments, log messages, error messages, CLI help texts, commit messages and documentation (README, AGENTS.md, new ADRs) (ADR 0031). Paperboy must support multiple languages and number/date formats; language and formatting belong in the templates (ADR 0024), not in code. The image texts currently built in (battery warning, stale bar, placeholder) remain German until templates exist. Existing ADRs 0012–0030 stay German.
- Adapt changes in structure and naming to the existing code.
- For larger requests (e.g. removing features or options, multiple files/ADRs affected), briefly summarize before implementation (what changes, what stays, risks) and carry them out only after confirmation by the user.
- Paperboy does not import any SolarAI packages; suppliers and Paperboy talk to each other only via HTTP.

## Versioning and decisions

- Git repository `github.com/maehld/paperboy`, branch `main`. After **every completed work step** create a commit with an **English** commit message in the imperative (ADR 0031). Run the appropriate checks before committing.
- Document significant decisions as ADRs under `docs/adr/` (template `0000-vorlage.md`, maintain the index `docs/adr/README.md`). ADRs 0012–0030 originate from SolarAI (0030 applies to both); new ADRs from 0032. Do not rewrite existing ADRs, supersede them with new ones.
- `paperboy.yaml` (contains the token), the local instance content (`pages/`, `plans/`, `providers/`, `icons/`, `state/`), the old `paperboy.json`/`displayd.json`, `paperboy-data/`/`displayd-data/` and `.env` are excluded via `.gitignore` and must not be committed or deleted.

## Architecture

Go **1.27 or newer**. Dependencies: `golang.org/x/image` **v0.24.0** (ADR 0013), `go.yaml.in/yaml/v3` **v3.0.5** (ADR 0024) and `tinygo.org/x/bluetooth` **v0.16.0** only in the package `internal/opendisplay/odble` (ADR 0016; the Paperboy binary does not contain it). Further dependencies only with their own ADR.

## Essential rules for devices

- **No upload endpoints:** pages come from templates selected by plans. A device without a plan, with a missing template or a broken plan gets a notice page, never an error.
- **Device API (ADR 0042):** plain HTTP status codes; `401` makes the firmware drop its key and register again by MAC, so a lost `state/devices.json` only costs the page cursor and the battery level. Image paths are relative; the device keeps the Paperboy URL it was configured with.

## Hardware findings

- **E1001** (MAC 44:1B:F6:85:AA:1C; findings below from the TRMNL firmware, 2026-10-17): battery voltage e.g. `4.08`, 4 gray levels look good. OpenDisplay: ID 0 = green button, 1 = the one to its left, 2 = the one left of that. ESPHome: buttons left→right GPIO5 = `previous`, GPIO4 = `next`, GPIO3 (green) = `home` (confirmed 2026-10-31 with firmware 0.4.0, which had the first two swapped), battery ADC GPIO1 ×2 with enable GPIO21; ESPHome's panel model is black and white only.
- **Sticky** (MAC B8:1F:3F:D8:6A:FC): ESPHome gray4 panel bands luma at 32/96/160 (map 0/85/170/255 into the bands); touch needs `swap_xy` + `mirror_x` + `mirror_y` with `rotation: 180`; power latch GPIO45/46 held through deep sleep; BQ27220 currents/capacities ×10.
- **Battery:** Sticky „Küche“ (“Kitchen”) 3.40 V after a long time without charging, E1001 „Wohnzimmer“ (“Living room”) 3.75 V; fluctuation approx. 0.02 V.
- **OpenDisplay firmware** (`cmd/odtest`): BLE under Windows on Sticky ODE46FD8 successful (reading configuration, test image 48 KB in approx. 31–33 s; not discoverable for a few seconds after disconnecting). Wi-Fi on reTerminal Sticky and E1001 successful (test image in native orientation). `-buttons` polls the 16-byte status block (`0x0044`) cyclically; Sticky (10.1.2.133): button on status byte 5, touch bytes 0–4. Byte 5 shows the last pressed button (ID 0 = top button, 1 = page up, 2 = page down) with **its own 4-bit counter per button**; short presses are often visible only in the counter → press = change of (ID, counter). Touch: contacts 1–5 = touched, 6 = released (coordinates remain); touch flags 0b111 (invert x/y, swap); coordinate range not yet calibrated.

## Planned work

ADR 0024 is implemented in its first two stages: the data document with path API, write timestamps per path and atomic storage (`internal/data`), and page templates that render from it (`internal/page`) with a preview endpoint (`GET /api/preview/{profile}/{page}`). ADR 0025 is implemented for devices on the device API: plans under `plans/<name>.yaml` with time rules, paging and rotation within a rule, refresh capped to the next rule boundary and notice pages instead of errors (`internal/plan`); a device without a plan gets a notice page. ADR 0026 is implemented except reloading: `paperboy.yaml` with top-level `language` and `timezone` (ADR 0033), `server`, `defaults`, `display_types` and devices as a map with stable IDs, strict validation, and `devices.json` migrated from MAC keys to device IDs. The image-upload pipeline was removed; OpenDisplay delivery is marked non-functional in the service (TODO). ADR 0033 configures the language and timezone globally; page templates and plans no longer carry `locale` or `timezone`. Still open from ADRs 0024–0027: configuration hot reload, plans/delivery for OpenDisplay, data conditions in plans (`when.data`) and push delivery to text displays (MQTT or ESPHome `web_server`).

ADR 0032 fixes the provider model on top of that: providers are external processes that push JSON into the shared document, pages are an operator-owned skeleton with named regions, and image fragments as well as Go plugins are rejected. Exec providers (local binaries that print JSON instead of posting it) are a possible later addition; the data document is the seam for that, no ADR yet.

ADR 0034 is implemented: page templates gain typography (`weight`, `size`, `shrink`, `align`), the box model (`padding`, `rule`, `divider`), the blocks `columns` (one level deep) and `bar`, tile `detail`, header `status` and `page_indicator`, the notice modes `bar|badge|none`, a chart with time axis, axes, ticks, "now" marker, area fills and series weights, and the template functions `now`, `page`, `pages`, `stale`, `below`, `above`, `ratio` and `time` for `time.Time`. The four SolarAI reference pages live in `examples/pages` (detailed and compact variants) and are covered by golden-image tests. The four existing installation templates remain valid; their typography follows the new defaults.

ADR 0035 adds the format `duration` (seconds as `42 min`, `2 h`, `3 h 20 min`) and moves the charge direction out of formatted texts: providers deliver `{seconds, charging}` and the template words it. The battery reference pages use it.

ADR 0036 adds exec providers: programs in `<instance>/providers` declared under `providers` in `paperboy.yaml` print the new value of one data branch as JSON, and Paperboy runs them on an interval and writes the result in process (`internal/provider`). Failures keep the previous data; the write time comes from a top-level `updated` or the run time; `PAPERBOY_LANGUAGE`/`PAPERBOY_TIMEZONE` reach every provider so language and timezone stay global. `cmd/weather` is the first provider (Open-Meteo, no API key) and feeds the `weather` branch; `examples/pages/wetter.*.yaml` render it. The chart now connects samples by timestamp distance (90 min) instead of pixel columns, so hourly forecast points draw a continuous curve.

ADR 0037 fixes the installation layout: `-config <dir>` names one instance directory (default `.`) that contains `paperboy.yaml`, `pages/`, `plans/`, `providers/` and `state/`. The `directories` section and `-data` are gone; `state/` is the only directory Paperboy writes and holds `devices.json` (the former `state.json`, device register with API keys, page cursor, battery level and active rule) and `data.json`. `pages/`, `plans/` and `providers/` stay operator-owned and are never created. There is no migration code: the README describes the manual move; a lost `devices.json` costs the page cursor and new device keys (devices re-register after a 401, ADR 0042).

ADR 0038 adds icons: a new `icon` block draws one PNG from the operator-owned `icons/` directory of the instance (mask from opaque dark pixels, trimmed margins, majority-vote scaling, optional caption), and the page chooses the file with a text template, so conditions like "apparent temperature below 15 °C or wind force above 3 → Pullover" stay in the template. The sample icons (`sun`, `cloud`, `rain`, `snow`, `thunder`, `tshirt`, `pullover`) in `examples/icons` come from OpenMoji (CC BY-SA 4.0, attribution next to the files). `cmd/weather` now also delivers `current.beaufort` and `current.symbol` (the pictogram name).

ADR 0039 extends `GET /api/devices` instead of adding a separate status endpoint: each device records the page it was last pointed at (`last_page`, `last_page_kind`, `last_page_hash`, `last_page_time`, `last_refresh`) and the last render or plan error (`last_error`) in `state/devices.json`, written after rendering; the API derives `last_page_url` and a `status` (`ok`, `late`, `never`, `unregistered`) from last contact and refresh, because devices deep-sleep and an idle display is not an offline one. Access stays unauthenticated; the HTML overview followed in ADR 0040.

ADR 0040 adds that overview: `GET /` redirects to `GET /ui`, a read-only operator dashboard rendered with the standard library's `html/template` from the embedded `internal/paperboy/ui/index.html`. It reuses `deviceInfos()` with the devices API, so status and content have one implementation; each card shows status, plan and active rule, a preview of the last served image (not a fresh render), refresh, last contact, battery and `last_error`. No JavaScript, no token, 30-second meta refresh. The header names the running build from `runtime/debug.ReadBuildInfo` (`dev` or the module version, short commit with `+dirty`, commit date in the configured timezone, Go toolchain in the tooltip), so no `-ldflags` or version file is needed.

ADRs 0041–0043 are accepted. ADR 0042 is implemented: the TRMNL API (`/api/setup`, `/api/display`, `/api/log`, `Update-Source`, `special_function`, 202 answers, absolute image URLs, key adoption, `friendly_id`, `public_url`) is gone in one step (user decision 2026-10-31, no parallel phase), so a display still on the TRMNL firmware gets no pages until it is flashed. ADR 0041 replaces the TRMNL firmware with our own firmware on ESPHome in `firmware/esphome/` (moved from branch `experiment/esphome-sticky` and switched to the device API): one image per hardware type (`sticky`, `e1001`), nothing installation-specific compiled in (Wi-Fi via captive portal or Improv, Paperboy URL in the device web UI, key by MAC), pinned ESPHome 2026.10.1, built outside Paperboy; both images compile, not yet flashed. ADR 0043 is implemented as well (`firmware.go`): Paperboy reads the operator-owned `firmware/<hardware>/<hardware>-<version>.bin` (never created; highest version part by part, MD5 cached per file mtime/size, other names logged once and listed on the dashboard), serves it at `GET /firmware/<hardware>/<file>` without a token, and offers `{version, path, md5}` in the sync when `firmware.update: auto` (default `off`), the device has no `firmware: hold`, the version differs (lower = rollback), the reported battery is at least `min_battery_volts` (default 3.6) and at no warning level (skipped for text displays, which run on mains power), and that version/MD5 has not failed three times. The next sync settles the offer (`firmware_pending`): same version → success, otherwise `firmware_failures` + 1; a new MD5 resets the count. Withheld offers are logged once per reason change (`updates off` and `held` stay quiet). `/api/devices` adds `firmware_available` and `firmware_status` (`current`, `offered`, `available` — an addition to the ADR for "newer image, no offer yet" —, `failed`, `held`, `none`). The firmware flashes right after the sync and reboots; the rollback test with a broken image is still open before `update: auto` is used on real devices.

ADR 0044 implements text displays on the device API and supersedes ADR 0027's `text-http`/`image-http` and per-device tokens. A display type with `kind: text` has `size: [columns, rows]` and `charset` (`utf8`, `ascii`, `hd44780`; `Profile.Kind`/`Charset`, width/height are columns/rows). Its page templates (`internal/page/text.go`, `LoadText`/`ParseText`) have `watch`, `notices: mark|none` and `lines` (Go templates with the usual helpers plus `pad`, `right`, `center`; not trimmed, converted to the charset, cut and padded, more lines than rows is an error; `!` in the last column of line 1 while stale). Text devices register and sync like ePaper devices; the sync answers `"image": null` plus `text {lines, hash}` and `listen_s` 0. `GET /api/device/text` (bearer device key; 409 for image displays) renders the cursor's page on a copy of the state (`choosePlanPage`/`renderPlan` with `quiet`, so nothing advances and nothing is logged every second), answers `204` for `?shown=<hash>` when unchanged and updates the shown content (`last_text`, `last_page*`, `last_error`) only in memory (ADR 0045). Notices become word-wrapped lines (`page.NoticeLines`); a critical battery shows its texts as lines; warn banners do not exist on text displays. `last_text` is stored in `state/devices.json`, shown in `/api/devices` and as an LCD block on the dashboard; the preview returns `text/plain`. Firmware `firmware/esphome/lcd2004.yaml` + `text-common.yaml` (ESP32 dev board, `lcd_pcf8574` 20×4 at 0x27, SDA 21/SCL 22, esp-idf): no sleep, register retried once a minute, sync at boot and every `refresh_s` but at most once a minute, text poll every `refresh_s` from the plan (one minute before the first sync; plan `refresh` may go down to `1s`, image displays keep a one-minute floor), setup hints on the LCD, OTA only from Paperboy's offer; `pb_hd44780` in `paperboy.h` maps ä ö ü ß ° µ to the A00 ROM. Compiles; not yet flashed (the existing display runs `pvmon.yaml` with Home Assistant and native OTA). Example page `examples/pages/solar-overview.lcd2004.yaml` with a render test.

## Startup and checks

```powershell
go run ./cmd/paperboy -config . -listen :8090
go test ./...
go vet ./...
.\scripts\build.ps1   # paperboy, odtest and weather into bin/<os>-<arch>/
```

- Apply `gofmt` to changed Go files.
- **Windows Firewall blocks per binary path (confirmed 2026-10-22):** `go run` starts the server from a new `%LOCALAPPDATA%\go-build\<hash>\…\paperboy.exe` each time, so every build is a new program for the firewall. A dismissed prompt leaves a permanent **inbound Block** rule for exactly that build: displays on the LAN get "connection refused" or timeouts, while `127.0.0.1` (SolarAI) keeps working. Check with `Get-NetFirewallApplicationFilter | ? Program -like "*paperboy.exe"` and prefer a stable binary from `.\scripts\build.ps1` (`bin\<os>-<arch>\paperboy.exe`) that is allowed once, instead of `go run`.
- **UTF-8 on Windows:** Windows PowerShell 5 reads UTF-8 files as ANSI, so a `Get-Content … | Set-Content …` round-trip turns „Für“ into „FÃ¼r“. Edit files with the dedicated tools, or read and write them with `[System.IO.File]::ReadAllText`/`WriteAllText` and `UTF8Encoding($false)`; never pipe source files through `Get-Content`/`Set-Content`.
- Prefer tests for protocol behavior and state transitions.

Keep this document up to date with relevant architecture or behavior changes.
