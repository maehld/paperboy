# Plugins

A plugin is a long-running program that provides widgets ([ADR 0049](../adr/0049-plugin-widgets.md)). Paperboy starts it on first use and sends its `config` section once (`configure`). Then it asks for widgets. Paperboy keeps the results until the `max_age` of the plugin (default 5 minutes) or until the plugin reports a change. It renders widgets that are still in use again in the background, so a device never waits for a plugin. When a plugin exits or does not answer within `timeout`, Paperboy restarts it. Until then, the last widgets appear as stale. A failing plugin is not asked again for a minute.

**Protocol** ([`docs/plugins/protocol.md`](protocol.md), `sdk/plugin`): one JSON object per line on stdin, one answer per line on stdout with the same `id`. Actions are `configure`, `state`, `describe`, `render` (`levels`: the tone count of the display, 1–256 — the canvas falls back to 2, 4 or 16 tones —, `widgets: [{widget, width, height, args, style}]` → base64 PNGs), `values` (the declared value keys of a text page → one value per key, [ADR 0111](../adr/0111-text-pages-from-plugin-values.md)), `actions` (the state of concrete actions) and `action` (run one). Every request carries `language`, `timezone`, `now` and the `page` (`title`, `number`, `count`, display `width`/`height`, and for image displays `ppi`).

**Protocol version 5** ([ADR 0050](../adr/0050-physical-scaling-by-display-ppi.md), [0057](../adr/0057-plugin-actions-from-the-plan.md), [0081](../adr/0081-plugin-state-over-the-protocol.md)): each widget's `style` holds `padding`, `rule` and `text_px` in pixels, already converted from the points of the page. Go plugins use `Request.TextPx`, `PtPx` and `MMPx` for physical sizes. `describe` lists widgets and, optionally, actions, plus the plugin's own `version` ([ADR 0075](../adr/0075-plugin-versions.md)). An action request names a concrete `action` and its `args` and gets `actions` states (title, disabled reason, confirmation) or a `result` (`ok`, `message`, `changed`). Between answers a plugin may print `{"event": "changed", "changed": ["agenda"]}`.

Right after `configure`, a protocol 5 plugin gets one `state` request with the stored JSON and its declared `blobs` (base64). Every answer may send new values back: missing = unchanged, `null` = forget the state. A plugin declares large values such as an image as `blobs` in `describe` ([ADR 0081](../adr/0081-plugin-state-over-the-protocol.md)). Paperboy writes `state/plugins/<id>/state.json` and `state/plugins/<id>/blobs/<name>` itself. A plugin keeps no files itself; Paperboy sets no `PAPERBOY_STATE_DIR`. It ends when stdin closes. Every plugin also sees `PAPERBOY_LANGUAGE` and `PAPERBOY_TIMEZONE` in its environment.

Every answer names the protocol version the plugin was built against (`"version": 10`). Paperboy requires at least 5 and accepts newer versions. Version 8 removed the text action; version 9 adds the schedule event; version 10 adds the action options. A plugin below 8 that still has text widgets is accepted, because nothing asks it for text. A plugin below 9 never receives a schedule. A plugin below 10 keeps the `actions` fallback for its options. It refuses a plugin below the minimum or without a version. A mismatch appears as the error of the cell and as one log line ([ADR 0058](../adr/0058-plugin-protocol-version-check.md)). The shipped data plugins use the schedule and require Paperboy 9; they read only when a display needs their data ([ADR 0126](../adr/0126-a-schedule-event-for-plugin-demand.md)).

A Go plugin implements `plugin.Handler` (`Describe`, `Configure`, `Render`). It can also implement `Valuer` (the declared values of a text page), `Preparer`, `Starter` (background work with a `notify` callback), `Ager` (`max_age`), `Actioner` (actions) and `Stater`/`Blober` (state and files Paperboy keeps between restarts). It calls `plugin.Serve` and draws with `sdk/render`: the fonts, gray levels, fills and icon masks Paperboy itself uses, so its widgets look like the rest of the page. It can also use the shared type scale and components of `sdk/design` ([Design language](../design/07-design-language.md), [ADR 0151](../adr/0151-a-shared-design-language-for-plugin-widgets.md)). Plugins in other languages speak the same JSON lines.

Paperboy ships the plugins below. One zip per platform (`paperboy-plugins-linux-amd64.zip`, `paperboy-plugins-windows-amd64.zip`) contains all of them. Unpacked in the instance directory, the zip creates `plugins/` with `<plugin>-v<version>`. Each plugin raises its version when it changes, and every plugin does when `sdk/plugin` or `sdk/render` changes ([ADR 0075](../adr/0075-plugin-versions.md), [0107](../adr/0107-plugin-builds-reach-installations.md)); a plugin that imports `sdk/design` or `sdk/format` raises its own version when that package changes. The version is in `plugins/cmd/<plugin>/VERSION`. Every plugin has its own documentation under `docs/plugins/`. Each page shows the example pages and the widgets of its plugin; `./scripts/screenshots.sh` renders the pictures ([Development](../development.md#writing-documentation)):

- [`evcc`](evcc.md) – PV, home, grid, battery, energy flow, loadpoints, forecast, the energy history of the day, week, month and year as a table or a bar chart, and evcc's values and charging statistics from [evcc](https://evcc.io); the first shipped plugin with actions, `evcc/mode` sets a charge mode from the loadpoint widget.
- [`dexcom`](dexcom.md) – the glucose reading of a Dexcom G7 from the Dexcom Share service: the value with trend and alarms, 24 hours and the last hour as a chart, the ambulatory glucose profile over several days, the numbers of 24 hours as rows, a child-friendly smiley for the state, and the `state` value for plan conditions.
- [`departures`](departures.md) – real-time public transport departures from an EFA installation.
- [`myskoda`](myskoda.md) – battery, charging plans, parking position and the vehicle image from the [MyŠkoda Public API](https://public.api.connect.skoda-auto.cz/docs).
- [`vicare`](vicare.md) – a Viessmann heating system from the ViCare cloud API: heating circuits, domestic hot water, burner or compressor, the heating curve and the device state, plus values for text pages.
- [`weather`](weather.md) – current weather and forecast from [Open-Meteo](https://open-meteo.com/), pictograms from [Weather Icons](https://erikflowers.github.io/weather-icons/).
- [`fuel`](fuel.md) – fuel prices around a location from [Tankerkönig](https://creativecommons.tankerkoenig.de): the nearest stations, the cheapest price and its history, plus values for text pages.
- [`calendar`](calendar.md) – agenda, week, month and birthdays from CalDAV and iCalendar.
- [`pokedex`](pokedex.md) – a Pokémon card from [PokéAPI](https://pokeapi.co).
- [`xkcd`](xkcd.md) – [xkcd](https://xkcd.com) comics.
- [`countdown`](countdown.md) – days to a date, optionally with a progress bar.
- [`rss`](rss.md) – RSS and Atom feeds as a list or as a single headline.
- [`github`](github.md) – open issues, open pull requests, failed workflow runs and the commit history of GitHub repositories.
- [`prusalink`](prusalink.md) – the state, progress and temperatures of a Prusa 3D printer from its local PrusaLink API.
- [`unifi`](unifi.md) – the state of a UniFi home network from the controller's integration API: device and client counts, offline devices and the short WAN summary, plus values for text pages.
- [`paperboy`](paperboy.md) – built in, no zip needed: header, title, text, clock, the Paperboy logo, the battery and the device status.
