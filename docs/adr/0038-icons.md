# 0038: Icons from the instance directory

- Status: Accepted
- Date: 2026-10-22
- Extends: ADR 0034 (layout primitives and typography), ADR 0037 (instance directory layout)
- Related: ADR 0024 (data document, templates), ADR 0032 (no image fragments or plugins), ADR 0036 (exec providers), ADR 0033 (language)

## Context

The weather page wants pictures, not only numbers: clothing advice ("Pullover" below 15 °C felt temperature or above wind force 3, otherwise "T-Shirt") and a small set of weather symbols. Today the template vocabulary has no graphics at all, and the obvious shortcuts fail:

- **Unicode symbols in text.** `goregular` and `gobold` (ADR 0013) contain no emoji or pictogram glyphs, so `👕` renders as an empty box.
- **Icon font.** A symbol font is a single large asset with its own licence, and none of the common sets contains a sweater; using an emoji font means shipping megabytes and losing control over the motifs.
- **SVG.** ADR 0024 rejected SVG with an external rasteriser, and a Go SVG library would be a new dependency with its own ADR.
- **Image fragments from providers.** ADR 0032 rejected them: a provider that ships pixels takes over typography, palette and scaling. Icons are the opposite case - static page assets that belong to the skeleton like fonts, not to the data.

What kind of graphic is actually needed? A single-colour pictogram that must look sharp on a 1-bit panel and identical on 4 gray levels, at one size per display type. That is a **mask**, not a photograph.

## Decision

We add a `icon` block and one operator-owned directory of PNG assets.

### 1. Directory and asset format

- Icons live in `<instance>/icons/`, next to `pages/`, `plans/` and `providers/`. Like them it is operator-owned: Paperboy only reads it and never creates it (ADR 0037).
- The format is **PNG** (`image/png` from the standard library, no new dependency). Assets are monochrome or grayscale with optional alpha; anything else is an error.
- Loading turns the image into a mask: alpha > 50 % where an alpha channel exists, otherwise luminance < 50 %. The mask is drawn as one solid colour, so the asset works unchanged on 1-bit and 4-gray panels.
- The asset is scaled with nearest neighbour to fit the target height, preserving the aspect ratio. Antialiased source pixels survive the mask as clean edges.

### 2. Block

```yaml
- name: kleidung
  icon:
    source: '{{ if or (below .weather.current.apparent 15) (above .weather.current.beaufort 3) }}pullover{{ else }}tshirt{{ end }}.png'
    align: center        # left, center (default), right
    size: 0.85           # fraction of the region height, default 0.85
    label: '{{ if or (below .weather.current.apparent 15) (above .weather.current.beaufort 3) }}Pullover{{ else }}T-Shirt{{ end }}'
    label_size: 0.2      # fraction of the label height, like text
    label_weight: bold
    padding: 4
```

- `source` is a **text template**, expanded like every other text field (ADR 0034). `or`, `below` and `above` are already available, so the clothing rule stays in the page and not in the provider.
- The short form `icon: tshirt.png` is accepted as `source: tshirt.png`.
- `label` is optional and is drawn below the icon; without it the icon alone fills the region. A label makes "icon above, word below" possible, which `columns` cannot express.
- `size` is the fraction of the region height the icon may use; `padding` is the distance to the region edges like in every other block.

### 3. Resolution and safety

- `source` is resolved relative to `<instance>/icons/`. Absolute paths and `..` are rejected, so a page cannot read arbitrary files.
- A missing or undecodable icon is a render error and leads to the notice page, exactly like a missing page template. A page that suddenly shows nothing is worse than a loud hint.
- The mask is cached per (path, file modification time, target height, palette) so that repeated renders of a device do not decode the same files again.

### 4. Sample icons

`examples/icons/` ships monochrome icons drawn for this purpose (no third-party licence): `sun`, `cloud`, `rain`, `snow` and `thunder` plus `tshirt` and `pullover`. They are generated by a small Go program (`examples/icons/gen.go`, build tag `ignore`) that draws the motifs, crops them to their ink and writes black-on-transparent PNGs; the files are the source of truth for the operator.

### 5. Weather data

The weather page needs a wind force, not a speed in km/h, and a picture name for the current condition. `cmd/weather` therefore adds `current.beaufort` (0-12) and `current.symbol` (`sun`, `cloud`, `rain`, `snow`, `thunder`) to the `weather` branch; `current.wind` stays in km/h for display. A template compares Beaufort and picks `{{ .weather.current.symbol }}.png`, so neither rule depends on the unit of a provider and the service stays free of source-specific knowledge.

### 6. Non-goals

- No colour, no photos, no alpha blending, no per-display-type variants of one motif (a second file is the answer).
- No icons from providers and no icon fonts; the mask block stays the only image path.
- No animation, no SVG.

## Consequences

- Pages gain pictures without pixels, fonts or palettes leaking into providers; the data document stays free of presentation.
- Operators can build or replace icons without touching Go code, and the instance directory stays the single thing to copy.
- Icons are one more asset type to version and back up with the instance, and one more directory that must exist before a page using icons renders.
- A 1-bit mask cannot show shading; motifs must work as silhouettes. On 4-gray panels the icon is black even though the panel could render a mid tone.
- Threshold flicker remains an operator decision: at 14.9/15.1 °C the symbol changes with the next refresh. Templates cannot express hysteresis, and moving the rule into the provider would contradict ADR 0034.
- `cmd/weather` gains `beaufort`, a derived value that belongs to the data (like the battery remaining time in ADR 0035), not to the page.

## Open questions

1. Do icons need a mid tone (`fill: shade`) for 4-gray panels, or is a solid silhouette enough for every motif?
2. Should a missing icon file be tolerated with a placeholder instead of a notice page after the first successful render?
3. Does the weather page need more symbols (fog, drizzle, hail), and should they follow the WMO code from the provider?
